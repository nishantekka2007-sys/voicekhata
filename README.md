# VoiceKhata

**A Gemma 4-powered, voice-first digital ledger for Indian micro-vendors.**

VoiceKhata is an open-source hackathon project exploring how shopkeepers and small vendors can record customer credit, payments, and shop expenses using natural speech instead of typing every transaction.

> **Project status:** Early development. Features described as planned are not yet guaranteed to be implemented.

## The problem

Small vendors often track customer credit in paper notebooks or by typing into apps. VoiceKhata aims to make recording a transaction faster through a simple voice-first workflow.

## AI-first approach

Our primary AI model will be **Gemma 4**. We will first evaluate an audio-capable instruction-tuned Gemma 4 variant (E2B or E4B) to see whether one model can transcribe speech and extract the transaction fields. Gemma 4 E2B, E4B, and 12B variants support native audio input; the exact choice depends on local hardware, inference support, and tests. See the [official Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4).

Preferred pipeline:

1. Capture a short voice recording.
2. Send audio to a supported local Gemma 4 audio model and request a transcript plus structured transaction data, if the chosen runtime supports this reliably.
3. Validate the returned fields in Python.
4. Let the vendor edit and confirm the transaction.
5. Save only confirmed transactions to SQLite.
6. Calculate customer balances with deterministic application logic.

**Fallback:** If direct audio input is not practical or reliable in the chosen runtime, use an open-source speech-to-text tool such as [faster-whisper](https://github.com/SYSTRAN/faster-whisper) for transcription, then pass the text to Gemma 4. This is a fallback, not a requirement to run two models from day one.

## Planned MVP

- Record or upload a short audio clip.
- Use Gemma 4 as the primary transaction-understanding model.
- Support Hindi, English, and Hinglish to the extent validated by testing.
- Show the transcript and extracted fields in an editable preview.
- Require explicit user confirmation before saving.
- Store confirmed transactions in SQLite.
- Show customer history, outstanding balances, and a basic daily summary.
- Provide typed input as a fallback when audio processing fails.

## Intended technology

- **Python** — application and deterministic ledger logic
- **Gemma 4** — primary AI model for audio/text understanding and transaction extraction
- **Ollama or another compatible local inference runtime** — model execution, subject to Gemma 4 audio support for the chosen version
- **Streamlit** — web interface
- **SQLite / Python sqlite3** — persistent local ledger
- **pytest** — automated tests
- **faster-whisper (optional fallback)** — speech-to-text if direct Gemma 4 audio input is not workable

We want to keep the stack small and avoid adding multiple AI services unless testing shows they are necessary. Model and runtime compatibility must be verified before the implementation is finalized.

## Safety and data integrity

- AI output must be validated before it can be saved.
- Transactions require explicit user confirmation.
- Balances must be calculated by deterministic application logic, not generated by the language model.
- Ambiguous or incomplete transactions must be sent back for clarification.
- Do not use real customer financial data in demos or tests.
- Do not commit secrets, private recordings, local databases, or downloaded model weights.
